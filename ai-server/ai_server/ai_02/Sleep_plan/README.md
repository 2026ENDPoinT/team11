# Sleep_plan 계산 모듈

최근 수면·설정·전체 시간표·일정에서 권장 취침·기상과 수면시간을 계산합니다. 기존 계산식과 모델 입력 양식은 유지합니다. HTTP 봉투 조립과 데이터 조회는 하지 않습니다.

이 문서는 **하위 계산기** 설명입니다. 실제 AI-02 HTTP 경로의 전처리·자원 검사·응답 조립은 [상위 서비스](../README.md)가 맡습니다. 원시 계산기/CLI는 now와 targetDate를 생략하면 현재 시각·기상일을 정하지만, 통합 HTTP는 두 필드를 반드시 받아 같은 입력 스냅샷을 재현합니다. 원시 계산기에는 시험 가산 기능이 남아 있으나 AI-02 HTTP에서는 비활성화됩니다.

- planner.py: 15분 후보, Process S, 수면 부족·규칙성 비용, 민감도와 규칙 폴백
- history.py: 35일 기록 정제·입면시간 처리·타임라인·Fatigue 입력
- analyze_plan(payload): plan의 원시 세 값과 내부 진단 반환. 해가 없으면 plan=null
- Fatigue는 현재 피로를 한 번 계산하며 기본 가중치 사용

후보는15분 격자에서 선택하며 KST 시계·기상일과 UTC 시간차를 사용합니다. 수면량은 기상−취침−입면시간입니다. 최소 수면 하한은 사용자 설정(기본300분, 허용240~480분), 최대 후보 수면량은600분입니다. 420분 이상 가능한 후보를 우선하고 부족하면 경고를 반환합니다. 현재 시각 이전 취침을 계획하지 않습니다.

관측 기상일5일 미만·최근 기록 오류/겹침·긴 미관측·오래된 기상·민감도60분 이상 등은 규칙 계획으로 전환합니다. 결과 mode=RULE/OPTIMIZED/UNAVAILABLE는 내부 계산 상태입니다. Fatigue의 평소 습관 입력은 최근7일 이전28일에서 만들고 개인화 가중치를 사용하지 않습니다. 실제 미래 피로 감소를 후보별 Fatigue 모델로 재예측하는 것은 아닙니다.

[입력·외부 API 명세](../../../docs/AI-02_BACKEND_CONTRACT.md)를 참고하세요. 내부 mode RULE/OPTIMIZED는 앱 PlanMode와 다릅니다.

CLI, 데모와 계산기 예제는 [보관 폴더](../../../dummy/ai_server/ai_02/Sleep_plan)에 있습니다. 운영 호출은 통합 서버로 보냅니다.
